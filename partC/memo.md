# Part C — Decision Memo: Casual Register for Indic Languages

**Scenario:** Product wants assistant replies in Hindi, Kannada, Tamil, Telugu, Bengali, and Marathi to sound casual/conversational rather than formal/textbook. Three paths: (a) SFT on casualized response pairs, (b) ≤1B inference-time rewriter model, (c) prompt-engineering only.

---

## Assumptions

- **Base model behaviour:** The base model already generates grammatically correct Indic outputs but defaults to a formal/encyclopaedic register — suggesting the casual register *exists* in its distribution but requires elicitation.
- **Reviewer throughput:** One native-speaker reviewer covering Hindi and Kannada, 10 h/week × 3 weeks = 30 reviewer-hours total. Assumed review rate: 8–10 example pairs/hour (writing + scoring a casualized pair is slower than just scoring). Upper bound: ~300 pairs across Hindi + Kannada only.
- **Data availability:** No pre-existing casual Indic conversation corpus. Synthetic pairs must be generated by prompting the base model and then human-corrected — no external API budget means the base model itself is the generator.
- **"Casual" as operational target:** A 3-point scale (1=formal, 2=neutral, 3=casual). Target: ≥60% of outputs rated 3 (casual) by the reviewer on a held-out 50-output sample per language.

---

## Back-of-Envelope Arithmetic

### (a) SFT path

| item | estimate |
|---|---|
| Reviewer pairs produced | 30 h × 9 pairs/h ≈ **270 pairs** (Hindi + Kannada only) |
| Avg tokens/pair (prompt + response) | ~400 |
| Total training tokens | 270 × 400 = **~108k tokens** |
| SFT epoch time on 1× A100-80GB | 108k tokens at ~500k tok/s effective throughput ≈ **< 1 min/epoch** |
| Realistic epochs needed | 3–5 fine-tuning epochs + eval iterations |
| **Verdict** | Compute is not the bottleneck. **Data is.** 270 pairs covering 2 of 6 languages is insufficient to generalise to Tamil, Telugu, Bengali, Marathi. Expect casual Hindi/Kannada but formal outputs on the other 4 languages. |

### (b) ≤1B rewriter model path

| item | estimate |
|---|---|
| Inference latency overhead | A 1B model on A100 at int8: ~10–15 ms/token decode. For a 100-token reply: **+1–1.5 s per request** |
| Training data needed | Same reviewer-produced pairs — same 270-pair coverage gap as SFT |
| Additional serving complexity | Second model in inference pipeline, ~2 GB additional GPU memory |
| **Verdict** | Same data gap as SFT, plus latency penalty and serving overhead. Strictly worse than SFT for the same data budget. |

### (c) Prompt-engineering path

| item | estimate |
|---|---|
| Training cost | **Zero** |
| Data collection | Zero — uses what exists |
| Day 1 readiness | Immediate |
| Ceiling | Bounded by base model's casual Indic distribution. Assumption: casual register is present but under-elicited — well-crafted system prompts + few-shot examples should raise casual ratings meaningfully. |
| Coverage | Works for all 6 languages simultaneously, not just the 2 reviewer-covered ones. |

---

## Recommendation: **Prompt-engineering first**

3 weeks is too short for a safe SFT cycle covering 6 languages with only 30 reviewer-hours of data. Reviewer coverage is Hindi + Kannada only; SFT on 270 pairs would leave Tamil, Telugu, Bengali, and Marathi untouched — those 4 languages would fail the launch review. A ≤1B rewriter has the same data gap with added latency and complexity. Prompt-engineering has zero training cost, covers all 6 languages from Day 1, and can be iterated daily within the 3-week window.

---

## Success Metric

Human reviewer rates ≥60% of test outputs as "casual" (score 3 on the 3-point scale) across a 50-output sample per language, across all 6 languages, measured at end of Week 2.

---

## Kill Criterion

If prompt-engineering does not achieve ≥50% casual ratings on Hindi and Kannada (the two reviewer-covered languages) by **Day 14**, abandon prompt-only and use the remaining week to run a narrow SFT on the Hindi + Kannada reviewer pairs for those two languages only, accepting that the other 4 will launch on prompt-engineering.

---

## Day 1 Experiment

Prompt the base model with 5 different system-prompt variants (e.g., varying explicitness of "casual/friendly" instruction, few-shot examples vs no examples, language-of-instruction: English vs native script) across all 6 languages. Have the Hindi + Kannada reviewer score 10 outputs per variant (= 50 scored outputs, ~2 reviewer-hours). Rank variants by casual rating to establish a baseline before any training pipeline is considered.
